ROTEIRO DA AULA 14 - MCP E IA NO DESENVOLVIMENTO
Passo a passo da demonstracao e links para abrir durante a aula.

Funciona no Windows (PowerShell), Linux e Mac: a parte principal so
precisa do Docker e do navegador. A parte com assistente de IA (passo 5)
precisa do Claude Code (ou do Copilot no VS Code) instalado e logado.
Todos os comandos abaixo sao digitados DENTRO da pasta:

    Aula 14/exemplo_tarefas_mcp


======================================================================
0. ANTES DE COMECAR
======================================================================

0.1  Abra o Docker Desktop e espere ficar "running".

0.2  Entre na pasta do projeto:

         cd "Aula 14/exemplo_tarefas_mcp"

0.3  Pare qualquer outra API que esteja na porta 8080
     (a Aula 13, a IDE etc.). So uma API pode usar a 8080.

         Linux/Mac:   ss -ltnp | grep 8080
         PowerShell:  netstat -ano | findstr :8080

     Se for um container da Aula 13:

         cd "../../Aula 13/exemplo_tarefas_resolvido"
         docker compose --profile app down
         cd "../../Aula 14/exemplo_tarefas_mcp"


======================================================================
1. SUBIR A STACK (API + banco + RabbitMQ + Prometheus + Grafana)
======================================================================

1.1  Suba tudo, inclusive a API (o Maven compila dentro do container):

         docker compose --profile app up -d

1.2  Confira:

         docker compose --profile app ps

     Esperado: postgres, rabbitmq e api "healthy" (a API pode levar
     1 a 2 minutos na primeira vez, porque baixa as dependencias,
     inclusive o Spring AI).

1.3  Se a api aparecer "Exited" (por exemplo, a 8080 estava ocupada
     na primeira tentativa), libere a porta e recrie so ela:

         docker compose --profile app up -d --force-recreate api

1.4  Confira se o servidor MCP subiu: no log devem aparecer
     "Registered tools: 5", "Registered resources: 1" e
     "Registered prompts: 1".

         docker compose logs api | findstr Registered      (PowerShell)
         docker compose logs api | grep Registered         (Linux/Mac)


======================================================================
2. O CLIENTE MCP DE BOLSO (sem IA)
======================================================================

2.1  Abra no navegador:

         http://localhost:8080/mcp.html

2.2  Clique em "Conectar". Mostre no painel da direita:
       - o initialize (o cliente se apresenta);
       - a resposta com serverInfo "tarefas", as capabilities e as
         instructions;
       - o notifications/initialized, que volta HTTP 202 (sem corpo).

2.3  Clique em "Listar ferramentas". Mostre:
       - as 5 ferramentas, com a descricao escrita para a IA;
       - o inputSchema (JSON Schema): os formularios saem dele;
       - "so leitura" x "altera dados" (annotations).

2.4  Em cadastrar_tarefa, preencha:
         titulo       Estudar MCP
         responsavel  Ana
         dataPrazo    (uma data da semana que vem, yyyy-MM-dd)
         prioridade   9
     Clique em "Chamar". Esperado: caixa vermelha
     "Dados invalidos. prioridade: Prioridade maxima e 5" e, no log,
     "isError": true.

2.5  Troque a prioridade para 4 e chame de novo. Esperado: a tarefa
     criada, ja com o id.

2.6  Tente a data 20/11/2026. Esperado: a mensagem pedindo o formato
     yyyy-MM-dd.

2.7  Chame estatisticas_tarefas. Depois "Ler tarefas://regras" e
     "Montar planejar_semana".


======================================================================
3. CONFERIR QUE E O MESMO SISTEMA
======================================================================

3.1  Abra o cadastro de tarefas (a tela da Aula 12):

         http://localhost:8080/

     A tarefa cadastrada pelo MCP esta na lista.

3.2  A mesma estatistica pela porta REST:

         http://localhost:8080/tarefas/estatisticas

3.3  No Swagger, a rota nova aparece em "Tarefas":

         http://localhost:8080/swagger-ui.html

3.4  (Opcional) O evento da tarefa criada pelo MCP passou pelo RabbitMQ:

         http://localhost:15674      (usuario e senha: tarefas)


======================================================================
4. AS MENSAGENS NO TERMINAL (opcional, so Linux/Mac/Git Bash)
======================================================================

4.1  O aperto de mao. Copie o valor do cabecalho Mcp-Session-Id:

         curl -s -D - -H "Content-Type: application/json" \
           -H "Accept: application/json, text/event-stream" \
           http://localhost:8080/mcp \
           -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'

4.2  A lista de ferramentas, com a sessao:

         curl -s -H "Content-Type: application/json" \
           -H "Accept: application/json, text/event-stream" \
           -H "Mcp-Session-Id: COLE-AQUI" \
           http://localhost:8080/mcp \
           -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'


======================================================================
5. UM ASSISTENTE DE IA DE VERDADE (Claude Code)
======================================================================

5.1  Abra o Claude Code dentro da pasta do projeto:

         claude

     Ele encontra o .mcp.json e pergunta se pode usar os servidores
     "tarefas" e "context7". Aprove.

     Sem o arquivo, o mesmo pelo comando:

         claude mcp add --transport http tarefas http://localhost:8080/mcp

5.2  Digite /mcp. Esperado: tarefas conectado, com 5 ferramentas.

5.3  Peca, um de cada vez, e mostre quais ferramentas ele escolhe:

     - Cadastra para a Ana: revisar o README do projeto, prazo sexta
       que vem, prioridade alta.
     - Quem esta com mais tarefas abertas? Tem alguma atrasada?
     - Conclui a tarefa 1 e me mostra como ficou o percentual concluido.

     Chame atencao para:
       - ele converte "sexta que vem" e "alta" sozinho (a descricao pediu);
       - as ferramentas so de leitura nao pedem permissao
         (.claude/settings.json); cadastrar pede.

5.4  O prompt pronto (aparece como comando):

         /mcp__tarefas__planejar_semana

     Argumento: Ana.

5.5  O recurso, anexado na mensagem:

         @tarefas:tarefas://regras  quais regras valem para cadastrar?

5.6  O Context7:

         use o context7: como declarar um @McpResource no Spring AI 1.1?

     Sem chave, o Context7 tem limite de uso. Se der erro de limite,
     mostre so a configuracao no .mcp.json.

5.7  Alternativa: GitHub Copilot no VS Code, modo Agent. Abra o
     arquivo .vscode/mcp.json e clique em "Start" acima de "tarefas".


======================================================================
5b. O ASSISTENTE NA TELA DE TAREFAS (sem chave, modelo local)
======================================================================

5b.1 ANTES DA AULA (precisa de internet, baixa ~2 GB uma vez so):

         docker compose --profile ia up -d
         docker compose --profile ia logs -f ollama-modelo

     Espere aparecer "success" e saia com Ctrl+C.

5b.2 Se a API esta no Docker, recrie-a para ela enxergar o Ollama:

         docker compose --profile app --profile ia up -d

5b.3 Abra:

         http://localhost:8080/assistente.html

     O selo no canto deve ficar verde: "modelo pronto".

5b.4 Peca, um de cada vez (cada resposta leva de 10 a 60 segundos
     no processador):

     - Como esta o andamento das tarefas?
     - Cadastre "Estudar MCP" para a Ana, prazo sexta que vem,
       prioridade 4
     - Quais tarefas estao atrasadas?

     Mostre o painel da direita: as ferramentas MCP que o modelo
     escolheu, os argumentos (a data ja convertida para yyyy-MM-dd)
     e o resultado de cada uma.

5b.5 Ligue "So leitura" e peca para concluir uma tarefa. O modelo
     nao consegue: ele nem recebe as ferramentas que alteram dados
     (readOnlyHint virando regra no host).

5b.6 Abra http://localhost:8080/ : a tarefa criada pelo assistente
     esta la.

5b.7 Explique o codigo: AssistenteService e o HOST. Ele faz, em Java,
     o mesmo ciclo do Claude Code: tools/list, pergunta ao modelo,
     tools/call do que ele pedir, repete ate vir texto.

5b.8 (Opcional, com chave) O mesmo codigo com o OpenRouter: copie
     .env.exemplo para .env, preencha ASSISTENTE_URL, ASSISTENTE_CHAVE
     e ASSISTENTE_MODELO e rode de novo o passo 5b.2.


======================================================================
6. IA NO DESENVOLVIMENTO: CLAUDE.md E SKILLS
======================================================================

6.1  Mostre os arquivos:

         CLAUDE.md
         .claude/settings.json
         .claude/skills/verificar/SKILL.md
         .claude/skills/nova-ferramenta-mcp/SKILL.md

6.2  No Claude Code, digite / e mostre que /verificar e
     /nova-ferramenta-mcp aparecem na lista, ao lado das skills do
     proprio Claude Code (/init, /code-review, /simplify...).

6.3  (Se der tempo) Rode o exemplo do workflow:

         Planeje a ferramenta reabrir_tarefa seguindo a skill
         nova-ferramenta-mcp. Nao escreva codigo ainda.

     Mostre o plano, aprove e deixe implementar. Depois:

         /verificar

     E por fim, para revisar o que foi feito:

         /code-review

     Para voltar ao estado original depois da demonstracao, veja o que
     mudou e desfaca so isso:

         git status
         git restore .

     (git restore desfaz as alteracoes em arquivos que ja existiam;
     arquivos novos que aparecerem no git status precisam ser apagados
     a mao.)
